SuperRack racks

Copying follows the patch: only strips with a link are touched, and it changes this sheet only. Push is what writes to the console or to SuperRack.

WING buttons

One row per USER button on the console. Pick what it does: nothing, SuperRack navigation, or one of SuperRack's 16 USER KEYS. The app sets the button up on the console (MIDI CC push) and writes the name you see on its screen.

USER KEYS: one-time setup in SuperRack
  1. On this Mac, once: Audio MIDI Setup → Window → Show MIDI Studio → IAC Driver: tick "Device is online", name a port WING Bridge, then restart this app.
  2. In SuperRack, add a MIDI Controller with input port IAC Driver WING Bridge.
  3. Press Write SuperRack MIDI file below, then in the MIDI Controller use Import MIDI Preferences and choose that file. It maps all 16 USER KEYS and navigation at once — no Learn needed. Send is still there to test a key.

Sessions

A session is the show: the patch sheet, the names and what each USER button does. The WING address, the interface, the ProLink port and the MIDI port belong to this machine and never change with the session. Editing does not save on its own: Save writes the open session, and a dot marks changes that are not in it yet.

Activity

Worth knowing

  • The patch starts locked. Unlock it to edit, and lock it again once the sheet is right — a stray click during a show would repatch a strip.
  • Mapping uses ShowRackByID, which takes the rack index. ShowRack takes the input index instead and opens the wrong rack — VOX is rack 23 but sits on input 31.
  • Opening a rack also opens the first plugin in it.
  • Zoom is the wheel with ctrl (or ⌘) held over the grid, or a pinch on the trackpad. It lasts while the window is open and starts at 100% every launch.
  • A strip links to exactly one rack. Clicking another crossing on the same row moves the link; clicking the same one clears it.
  • The same rack on two strips is flagged as a conflict.
  • Moved racks. Each link remembers the rack's SuperRack name. If racks are reordered and a link now points at a rack with another name, it is flagged ⚠ with a hollow mark, and the app will not open it on strip select. Relink by name follows the original name; Keep as is accepts the rack now there.
  • DCAs are absent on purpose: a DCA controls the gain of other channels but carries no audio, so it has no insert and no rack. The WING's selidx only covers channels, aux, buses, main and matrix.
  • Hatched columns are rack slots SuperRack has not named — it still calls them Rack 35, Rack 36 and so on. They are linkable like any other.
  • A link follows the rack, never the audio patch. Channel 1 to rack 1 stays channel 1 to rack 1 whatever is fed into that rack, and repatching audio mid-session does not move it. The reverse holds too: this app never writes audio routing — the only things it sends are which rack to show and, if you ask for it, names.
  • SuperRack needs Assign ticked once in its ProLink dialog. After that it reconnects on its own whenever the app starts — the app always presents the same console identity.
  • The rack count follows SuperRack: it is read from the inventory the console sends, not set here.

About

Kite

An independent tool that links console strips to rack views. It reads the console's selection and asks the rack host to show a rack; it never writes audio routing. Names are written only when you ask for it.
